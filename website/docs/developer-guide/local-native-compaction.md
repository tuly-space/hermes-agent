# Local native Responses compaction

The local integration preserves upstream's GPT-5.6 route gates and exact `gpt-6-astra` support on official Codex OAuth. On the explicitly verified local proxy below, it additionally supports the GPT-6 family (`gpt-6`, `gpt-6-astra`, and dotted version variants); unrelated names such as `gpt-60` are excluded. This exception does not enable GPT-6 on arbitrary custom or direct API routes.

In addition to existing direct OpenAI support, the verified local Codex proxy route is allowed: `https://us-lrv03-sj4srl0f0-react-work.taila837d.ts.net/v1`. If provider identity is available it must be `custom:local-codex-proxy` (or normalized `custom`). This explicit endpoint allowlist is shared by capability resolution and request gating; arbitrary custom providers remain denied. Existing explicit runtime denial, checkpoint requirements, and compression-disable switches remain authoritative.

Live verification with `gpt-6-astra`: `/responses` plus `context_management=[{"type":"compaction","compact_threshold":1024}]` returned a compaction item; replaying only that encrypted item recalled all three fictional facts. The standalone `/responses/compact` route returned 404 and is not used.

Local source changes require a separately authorized Gateway restart before existing processes use them. The configured production threshold is unchanged.

## Unified automatic decision (local integration)

Automatic compaction is admitted at the assembled pre-API request gate, once per measured request. It combines the resumed-session idle gap, request token pressure, the configured Gateway hard message limit (counted on the effective checkpoint-pruned request, not archived rows), and engine preflight maintenance into one reasoned decision and one `_compress_context` chain. Tool results are checked by the next pre-API gate; the Gateway no longer runs a competing hygiene summary and turn-start/post-tool code does not start another automatic summary. With compression disabled, Gateway's existing input bound remains payload-only. With compression enabled, the Agent checks the effective message limit; a blocked over-limit request is deferred rather than sending the full transcript. Manual `/compress` and provider-proven overflow retain their separate entry points and commit fences.

Native checkpoint success waits for real provider usage before reconsidering pressure, regardless of retained raw history. Checkpoint readiness and the usage latch inspect the same normalized, assembled API view used for request pressure and effective message count; neither rewrites archived history nor weakens checkpoint prefix validation. Refused native attempts carry a concrete diagnostic reason (such as transcript content/length mismatch, watermark mismatch or revoked commit admission) through the deferred result. Gateway logs that reason rather than assuming all deferrals are concurrent lock contention. An ordinary summary may be remeasured and retried within the existing attempt/progress budget. Admission preserves cooldown, lock, cancellation, review-fork and compression-disable guards. A combined decision emits only the existing status appropriate to its context (idle on cold resume, automatic during an active turn); fallback does not issue another start status. No background idle timer is introduced.

## Native maintenance and next-turn idle compaction

`compression.idle_compact_after_seconds` uses the existing turn-start gap trigger; it does not schedule background work. The existing idle size, cooldown, and lock guards determine whether a pass runs. Hermes emits its existing idle compression status when a pass is admitted; the gateway delivers this idle-resume status without enabling other routine compression progress (`compression.progress_notices` remains their gate).

`auxiliary.compression.native: true` permits the supported Sol auxiliary route to attempt an inline `/responses` checkpoint when the existing compression flow admits a pass, including idle resume. `auxiliary.compression.preserve_reasoning: true` retains eligible encrypted reasoning on that route. A completed response without a compaction item falls back to the ordinary summary. Raw transcript rows remain intact and checkpoints are persisted on assistant rows. The pre-API native attempt uses the existing progress-aware compression waiter and the same commit fence. Its idle budget is at least the effective `auxiliary.compression.timeout`, with a bounded total ceiling; an explicitly disabled summary watchdog still leaves the native request bounded by the auxiliary budget. No detached Gateway hygiene wait races it. Cancellation or stale-input/CAS refusal forbids both late checkpoint publication and ordinary-summary fallback on the old input. These are host-side budgets, not a guarantee of provider-side deadlines.
